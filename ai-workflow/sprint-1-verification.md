## Memory settings and the 2 GB override

`ai-workflow/sprint-1.md` Step 3 specifies a 4 GB DuckDB limit. The project owner overrode it: the pipeline runs with `memory_limit = 2GB`, 4 DuckDB threads, insertion order off, spill to `data/duckdb_tmp`, and dbt threads 1 (`analysis/funnel/common.py`, `pipeline/profiles.yml`). Reason: on this machine a 4 GB ceiling left too little headroom; available memory (`\Memory\Available MBytes`) stood near or below the 3 GB gate that every heavy run must pass, so a 4 GB limit could exceed the memory actually available. The sprint brief is left as written; the override is recorded here and in `ai-workflow/correction-log.md`.
