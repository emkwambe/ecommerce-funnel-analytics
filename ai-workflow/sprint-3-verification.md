## Step 3: Tableau Public publishing check (evidence only)

**Question (plan, Step 3):** can a workbook built only from the committed aggregate exports be published to Tableau Public without exposing row-level data? The dataset license question was settled in Sprint 0 (`docs/data-source.md`: aggregates and findings only, with attribution) and is not reopened here. Nothing was built in Tableau.

**What Tableau's current official documentation says**, verbatim. Every sentence below was located by exact string match in the page text. The URLs, retrieval time (2026-09-27 01:17 UTC), page hashes, and match results are in `ai-workflow/evidence/sprint-3/tableau_public_docs_quotes.txt`.

From [Tableau Public FAQ](https://help.tableau.com/current/pro/desktop/en-us/public_faq.htm) ("Applies to: Tableau Public"):
> "Workbooks and data published to your Tableau Public profile are not private and are freely accessible to anyone."
>
> "Note : Anyone who knows (or stumbles across) the URL for the viz can see it, so be sure not to use this service for data that isn’t meant for sharing."
>
> "By default, any Tableau Public viz as well as the underlying data can be downloaded by clicking the Download link in the lower right corner of the viz. The workbook (TWBX file) can be opened by anyone with Tableau Desktop (Professional or Public Edition). You can toggle off the ability to download the workbook and the underlying data set in the viz settings. You can also set the default behavior for new vizzes in your profile settings."
>
> "Tableau Public only supports extracted data sources, and does not support live connections to data."
>
> "Tableau Public is limited to 15M rows of data per workbook."

From [Save Workbooks to Tableau Public](https://help.tableau.com/current/pro/desktop/en-us/publish_workbooks_tableaupublic.htm) ("Applies to: Tableau Desktop, Tableau Public"):
> "Workbooks and data published to your Tableau Public profile are not private and are freely accessible to anyone."
>
> "On Tableau Public, anyone can interact with your views, or download your workbooks or data sources."
>
> "When you save a workbook to Tableau Public, the publishing process creates an extract of the data connection."

**Reading.** Whatever data a Tableau Public workbook contains should be treated as public and downloadable. Publishing makes an extract of every data connection, and viewers can download the workbook with its underlying data by default. The download toggle exists, but the same pages state that published data "are not private and are freely accessible to anyone", so the toggle is not relied on as a control. What a workbook exposes is therefore exactly its data sources.

**Answer: yes, on one condition.** A workbook whose only data sources are the committed aggregate exports (`web/public/data/*.json`, or tables derived from them) exposes nothing beyond what the site and the public repository already publish. The condition is on our side and is checkable:

- the exports are aggregates. `analysis/tests/test_no_row_level_data.py` (`test_committable_files_have_no_row_level_data`) fails if any committed file under `web/`, `docs/`, or `ai-workflow/evidence/` holds row-level event data;
- the workbook must connect to nothing else: not the Parquet file, not `data/warehouse.duckdb`, and not any file under `data/`.

When a Tableau workbook is built, it should record its data sources in `ai-workflow/` and add a check that each one is a committed export, since the download toggle is not a control. That is a proposal for the sprint that builds the workbook; nothing is built now.

**Uncertainty:** none new. The documentation is unambiguous that published data is public and downloadable, and the answer doesn't depend on the toggle. The only thing that could make the answer wrong is a workbook connected to a non-aggregate source, and the condition above excludes that.

## Sprint 3 outcome: the ranking stopped (option D)

By the owner's closing decision (2026-09-27), the category ranking defined in the `docs/metrics.md` entry "2026-09-26 · Sprint 3: category session conversion and its size-adjusted ranking" is **stopped**. **Nothing from it is published.**

- **Why:** the pre-registered separability rule (two categories are different only where their 90% rank intervals don't overlap) **failed its synthetic-null calibration, stop rule F6**. On synthetic data where all 13 categories have the same expected conversion, the committed ranking code at the real settings (2,000 user-clustered resamples, seed 20260926) separated at least one pair in 3 of 6 datasets, with no clustering and no permutation involved (`ai-workflow/escalations/2026-09-27-C-rankings-stop-rules.md`, §2; search-log row 42). A rule that reports differences where none exist can't be trusted to separate real ones.
- **Runs:** no ranking result was ever used. Run 1 crashed, run 2 was stopped by Claude Code for low memory, run 3's outcome is unknown, and run 4 is void (search-log rows 37–41). R2 was not run.
- **What stays:** the Step 4 code, the provenance guards, the escalation brief (committed in this PR), and the approved 2026-09-26 entry, as the pre-registration that the negative control tested. The withdrawn option A draft was never approved.
