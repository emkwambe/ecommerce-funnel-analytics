# CLAUDE.md — E-commerce Funnel Analytics (ecommerce-funnel-analytics)

## What this project is

A public portfolio project that analyzes a large real e-commerce event log (view, cart, and purchase events) to answer one business question: **Where in the view-to-purchase funnel do sessions most often end with no observed purchase, which categories hold the most carted value with no observed purchase in the session, and what should the team test first?**

It demonstrates:

- an AI-built SQL pipeline (dbt on DuckDB) with a documented metric layer;
- KPI dashboards, on the web and in Tableau Public;
- a stakeholder-style data discrepancy investigation;
- a natural-language-to-SQL agent that answers only through defined metrics, behind a SQL safety guard, and is scored on a golden question set.

It is also an explicit record of how Claude Code was used under a human-in-the-loop workflow. `ai-workflow\` is a deliverable.

Tier: Governed (from Sprint 2): branch → PR → CI → Copilot review (if available) → owner merge. Never push to main directly.

It is the second project in a series. The first is `emkwambe/email-experiment-readout`, and the same verification standards apply.

## Non-negotiable rules

1. **No uncomputed numbers.** Every number on the site, in the README, in docs, or in Tableau comes from code in this repo reading the data. Never type a statistic by hand.

2. **Sourced interpretation.** Every interpretive sentence on the site cites the exported fields that support it. Tests verify numbers; human review verifies conclusions.

3. **Metric lock (lifted by the contract).** `docs\metrics.md` was committed in `8d4093f`. Business metrics may now be computed, **only as defined in `docs\metrics.md`**. That covers conversion rates, revenue, and funnel rates, including breakdowns by category, brand, product, time period, or user segment. A metric the contract does not define may not be computed, published, or answered until a dated Changes entry defines it. Before that commit, Sprint 0 was limited to structural profiling:
   - schema, types, row counts;
   - null rates;
   - duplicate counts;
   - value ranges;
   - overall event-type counts;
   - date range;
   - ordering anomalies.

4. **Metric definitions are the contract.** Once committed, `docs\metrics.md` changes only through a dated entry in its Changes section, with reason and effect. The dashboards and the agent may only use defined metrics.

5. **Provenance.** Every JSON export carries a manifest block: git commit SHA, dataset SHA-256, UTC timestamp, and script name.

6. **Reproducibility.**
   - `python -m funnel.ingest` fetches the data and regenerates `docs\data-source.md`; it is a provenance event, run rarely.
   - Everything else regenerates from the ingested data with one command per stage. Stage commands halt if the dataset hash doesn't match `docs\data-source.md`.

7. **Correction log.** Every error made by Claude Code or Claude Chat and caught by a test, a check, or human review goes into `ai-workflow\correction-log.md`, in the same commit as the fix. Record its origin and how it was caught.

8. **Evidence, not claims.** Report the exact commands run and their actual output. Gate every commit on pytest's own exit code, using `set -o pipefail` or `PIPESTATUS`, never on a piped command's exit code.

9. **Stop and escalate.** Stop and report at any failed check, license restriction, or ambiguity in a spec. Never resolve ambiguity silently. The human owns the decisions.

10. **Safe operations.**
    - Never run `rm` or delete on a variable path without a `${VAR:?}` guard or a literal path.
    - Keep temporary scripts in the scratchpad, never in committed folders.
    - Never rewrite git history.

11. **Names.** Project and page names are descriptive. Any brand-like name is checked with a web search for existing companies or products before use.

## Style

- **Python:** type hints, small pure functions, DuckDB SQL for anything over the raw data (the data is too large for pandas in memory), and pandas only on small aggregates.
- **dbt:** staging → intermediate → marts, with every model documented and tested.
- **Web:** decision-first readouts, intervals or counts shown beside rates, plain business language, and numbers read from JSON at build time.
